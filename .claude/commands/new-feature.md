PLAN.md에서 Must 항목 중 하나를 선택해 구현한다.

## 사전 조건
- AI_DOCS/ 전체를 먼저 Read 했는가? (아니면 멈추고 읽기)
- 현재 어느 모드인가? CODE 모드 확인.

## 절차

1. **PLAN.md Read**
   - 사용자가 인자로 항목 번호 (예: "1A.2")를 줬으면 그것
   - 안 줬으면 *미체크 P0 항목 중 첫 번째*를 선택

2. **6슬롯 컨텍스트 작성** (methodology.md §3)
   ```
   1. 과제: (한 문장)
   2. 읽을 파일:
      - AI_DOCS/workflow-9-steps.md (해당 Step)
      - packages/types/index.ts (관련 타입)
      - 기타 관련 파일
   3. 따라야 할 패턴: (기존 어느 파일 본뜰지)
   4. 제약: (성능/스타일/보안)
   5. 범위 밖: (이번에 하지 않을 것 — 절대 비워두지 말 것)
   6. 완료 기준: (관찰 가능한 성공 조건)
   ```

3. **사용자에게 6슬롯 확인** — 검토 받은 후 진행
   - 불명확한 부분이 있으면 *질문*. 추측 금지.

4. **별도 브랜치 생성**
   ```bash
   git checkout -b feat/<기능명>
   ```

5. **구현**
   - 한 번에 하나의 변경
   - 매 커밋이 통과 가능 상태
   - TDD 영역(Agent tools, 비즈니스 로직)은 테스트 먼저

6. **검증**
   - 테스트 실행 후 통과 확인
   - UI 변경 시 브라우저로 확인
   - DB 변경 시 실제 쿼리로 확인

7. **커밋 + 푸시**
   ```bash
   git add .
   git commit -m "feat: <간단한 설명>
   - 상세 1
   - 상세 2"
   git push -u origin feat/<기능명>
   ```

8. **PLAN.md 체크박스 업데이트**
   - 별도 commit으로 분리 (Tidy First)

9. **사용자에게 PR URL 보고**
   - 다른 사람(또는 Reviewer agent)이 리뷰할 수 있도록

## 절대 하지 말 것

- AI_DOCS 안 읽고 시작
- 6슬롯 안 채우고 코드 작성
- 범위 밖 작업 추가
- main 브랜치에서 직접 작업
- 테스트 없이 머지

## 인자

$ARGUMENTS — 선택사항. PLAN.md 항목 번호 (예: "1A.2") 또는 기능 설명.
