현재 브랜치 또는 지정된 PR을 리뷰한다.
이 명령은 *Reviewer agent* 역할로 실행된다.

## 절차

1. **변경사항 파악**
   ```bash
   git diff main...HEAD
   ```

2. **methodology.md §5 Taste 기준 적용**
   - 작동하는 코드 vs 좋은 코드 구별
   - 매직 넘버 / 매직 스트링 발견
   - 중복 로직 발견
   - 명명이 의도를 드러내는가
   - 한 함수가 한 가지만 하는가

3. **체크리스트 검증**
   - [ ] CLAUDE.md §9 "완료 점검표" 통과
   - [ ] 6슬롯 컨텍스트의 "범위 밖" 항목이 *진짜로* 범위 밖에 머물렀나
   - [ ] 테스트가 *실제로 의미 있는* 것을 검증하나 (smoke test에 그치지 않나)
   - [ ] 커밋 메시지가 *왜*를 설명하나
   - [ ] 구조적/행동적 변경이 분리되어 있나 (Tidy First)
   - [ ] AI_DOCS 업데이트가 필요한 학습이 있나

4. **출력 형식**
   ```
   [Reviewer 리뷰: feat/<기능명>]
   
   ✅ 잘된 점
   - ...
   - ...
   
   ⚠️ 개선 권고
   - 파일:라인 — 설명
   - 파일:라인 — 설명
   
   🚫 머지 차단
   - 파일:라인 — 이유 (있을 때만)
   
   💡 학습 기회
   - AI_DOCS/<파일>.md에 추가할 내용:
     ...
   
   판정: APPROVE / NEEDS_REVISION / BLOCK
   ```

5. **Taste 코멘트 예시**
   - "함수 이름이 동작을 안 드러냄. `process()` → `validateAndSavePosterImage()`"
   - "이 매직 스트링 `'order_open'`이 3곳에 있음. types/index.ts의 FlowStage로 통합"
   - "이 try-catch는 에러를 삼킴. 로그도 안 남김. 디버깅 불가."

## 절대 하지 말 것

- 칭찬만 하기 (의미 없음)
- 모호한 코멘트 ("이 부분이 좀 이상해요")
- *어떻게* 고칠지 안 알려주기
- 작성자가 만든 결정을 *근거 없이* 뒤집기
