# Client Requirements

> 클라이언트와의 합의 사항 + 결정 사항. 모든 작업이 이 문서와 정렬되어야 함.
> 변경 시 반드시 `decisions/` 에 ADR로 기록.

---

## 클라이언트 프로필

- **업종:** 한국 오프라인 매장 (유통/리테일)
- **사용자 연령:** 비교적 시니어층 (디지털 친화도 낮음)
- **현재 운영 방식:** 카카오 오픈채팅 + 엑셀 + 수기 메모
- **목표:** 모든 운영 업무를 *1클릭*으로 자동화

---

## 핵심 가치 제안

> "메뉴얼한 워크플로우가 다 자동화 되고, 대화를 통해 에이전트가 업무의 상황과 일정, 할일을 보고하고 *모든 human work가 최소화*되는 것."

**Human input 최소화:**
- *유일한 입력*: 상품 발주 정보 (Step 1)
- 그 외 모든 단계는 AI가 자동 처리

**대화형 인터페이스:**
- Agent Chat 패널에서 자연어 명령
- Execution Trace 패널에서 실시간 진행 확인

---

## Must (이번 스프린트 안에 반드시)

| 항목 | 우선순위 |
|---|---|
| 상품 등록 → DB 저장 | P0 |
| AI 공고① 텍스트 자동 생성 + 복사 버튼 | P0 |
| 네이버 가격 크롤링 (자동, Playwright) | **P0** ← 클라이언트가 명시적으로 자동화 요청 |
| 이미지 합성 (기존 이미지 + 텍스트 오버레이) | P0 |
| 주문 웹 (랜딩 + 주문 폼) | P0 |
| 대시보드: Agent Chat + Execution Trace | P0 |
| 도매업자 이메일 자동 전송 | P0 |
| 수령 안내 공고③ 자동 생성 | P0 |
| 모든 워크플로우 1클릭 트리거 | P0 |

## Should (시간 남으면)

- 주문조회 웹 (카운터용)
- 수령날짜 비교 테이블 자동 생성
- 캘린더 시각화 (대시보드 내)
- Stage 2 공고 (주문 마감 임박)

## Won't (이번 스프린트 제외 — 다음 스프린트로)

- **카카오 API 자동 전송** → 텍스트 복사로 대체 [클라이언트 합의]
- 결제 시스템
- 회원가입/로그인
- 다국어
- 다중 매장 (multi-tenant)
- 모바일 앱
- 푸시 알림

## 제약 사항

### 데이터
- 모든 가격: 정수 (원), 천단위 콤마는 표시 시점에
- 모든 날짜: ISO 8601 (DB) → "MM월 DD일(요일)" (UI 표시)
- 한글 우선 (영문 UI 금지, 단 라벨 일부 예외)

### 외부 API
- 카카오 API 사용 안 함 (이번 스프린트)
- 네이버 크롤링: rate limit 엄수 (`naver-crawl-strategy.md` 참조)
- 이메일 전송: Resend API (도매업자 통지용)

### UI/UX
- *시니어층 친화*: 큰 버튼, 명확한 라벨, 한글 우선
- 대시보드는 데스크탑 우선 (매장 PC 사용)
- 주문 웹은 모바일 우선 (고객 카카오톡에서 링크 클릭)
- 주문조회 웹은 데스크탑 (카운터 PC)

### 성능
- 페이지 로드: 3초 이내
- Agent tool 실행: 30초 이내 (네이버 크롤링 포함)
- 응답 없으면 사람에게 에러 명확히 알림 (추측 채움 금지)

## 의사결정 로그 — 클라이언트와 합의된 사항

### 2025-05-13 결정

**Q: 카카오 자동 전송?**
A: 텍스트 생성만. 복사 붙여넣기 UI.
*이유:* 카카오 오픈채팅 공식 API 없음. 비공식 자동화는 차단 위험.

**Q: 네이버 크롤링 자동/수동?**
A: 자동. Playwright 사용.
*이유:* 클라이언트가 명시적 자동화 요청. rate limit 엄수로 안전성 확보.

**Q: 이미지 생성 vs 합성?**
A: 합성. 관리자가 기존 이미지 업로드 → 텍스트 오버레이.
*이유:* 클라이언트가 자체 이미지 보유. AI 생성 이미지는 브랜드 톤 불일치 위험.

## 변경 관리

이 문서 변경 시:
1. 변경 사유를 `decisions/DECISIONS.md`에 기록
2. 영향받는 AI_DOCS 파일 같이 업데이트
3. PLAN.md 우선순위 재검토
4. 영향받는 작업이 진행 중이면 즉시 중단 → 재plan

**클라이언트가 도중에 변경 요청 시:** Won't 항목은 *이번 스프린트 거부*. Should/Must 변경은 *영향도 분석 후 응답*.
